1. Meet the function toolkit

A function accepts one or more inputs, does one focused job, and returns a value. You can use that returned value in SELECT, WHERE, ORDER BY, and many other SQL clauses.

Analogy: the labeled kitchen drawer

You would not use a measuring cup to slice bread. SQL functions work the same way: choose the small tool that matches the job. TRIM() cleans text, ROUND() shapes a number, DATEDIFF() measures time, and RANK() compares rows.

Text

String functions

Clean, join, measure, search, and split character data.

Quantities

Numeric functions

Round values, find magnitudes, and support calculations.

Calendar

Date/time functions

Parse, format, add, subtract, and search dates safely.

Context

Window functions

Rank a row or compare it with related rows without collapsing the result.

AP stays read-only in this chapter

Every data-access query here is a read-only SELECT. The initial USE ap selects the schema; it does not edit its tables. Confirm your active schema and do not change the publisher-provided fictional data.

Safe starting point 
USE ap;

SELECT DATABASE() AS active_database,
       COUNT(*) AS vendor_count
FROM ap.vendors;

Two mental models

  • Scalar function: one input row produces one calculated value, such as UPPER(vendor_name).
  • Window function: the current row stays visible while MySQL also looks across a related set of rows.

2. Work with string data

String functions are the label maker and scissors of SQL. They can change case, remove unwanted spaces, extract part of a value, and assemble a readable result.

Common string-function jobs
Job Useful functions Beginner reminder
Clean TRIM(), LTRIM(), RTRIM() The query result changes; the stored row does not.
Measure CHAR_LENGTH(), LENGTH() Characters and bytes are not always the same.
Extract LEFT(), RIGHT(), SUBSTRING() Positions begin at 1 for ordinary positive indexes.
Combine CONCAT(), CONCAT_WS() A NULL argument makes CONCAT() return NULL.
AP string-function tour 
SELECT vendor_name,
       UPPER(vendor_state) AS state_code,
       TRIM(vendor_phone) AS clean_phone,
       LEFT(vendor_zip_code, 5) AS zip5,
       CHAR_LENGTH(vendor_name) AS name_characters,
       LENGTH(vendor_name) AS name_bytes
FROM ap.vendors
ORDER BY vendor_name
LIMIT 10;

Characters versus shipping weight

CHAR_LENGTH() counts the letters a reader sees. LENGTH() counts the bytes used to carry those letters. With utf8mb4, one character can require several bytes.

One character, two bytes in utf8mb4 
SELECT LENGTH(_utf8mb4'é') AS bytes_used,
       CHAR_LENGTH(_utf8mb4'é') AS characters_seen;
-- Result: 2 bytes, 1 character

Build an address without losing it to NULL

CONCAT compared with CONCAT_WS 
SELECT vendor_name,
       CONCAT(vendor_address1, ', ', vendor_address2) AS risky_address,
       CONCAT_WS(', ',
                 vendor_address1,
                 vendor_address2,
                 vendor_city,
                 vendor_state,
                 vendor_zip_code) AS mailing_address
FROM ap.vendors
ORDER BY vendor_name
LIMIT 10;

CONCAT() returns NULL if any argument is NULL. CONCAT_WS() skips NULL values after its separator, although it does not skip empty strings.

3. Parse strings and sort numbers stored as text

Parsing means taking one packed label and separating useful pieces. It is like reading the building, room, and seat from “SCI-204-B.”

Parse a structured code 
SELECT SUBSTRING_INDEX('ACME-2026-0042', '-', 1) AS vendor_code,
       SUBSTRING_INDEX(
           SUBSTRING_INDEX('ACME-2026-0042', '-', 2),
           '-', -1
       ) AS invoice_year,
       SUBSTRING_INDEX('ACME-2026-0042', '-', -1) AS sequence_number;

LOCATE()

Finds where a smaller string begins inside a larger string.

SUBSTRING()

Returns characters beginning at a position you specify.

SUBSTRING_INDEX()

Returns text before or after a repeated delimiter.

REPLACE()

Returns a copy with matching text replaced; it does not update the column.

When “100” sorts before “20”

Text sorts character by character, so a text value of '100' can come before '20'. Convert only when the column truly contains numeric text.

Numeric-only invoice numbers 
SELECT invoice_number
FROM ap.invoices
WHERE REGEXP_LIKE(invoice_number, '^[0-9]+$', 'c')
ORDER BY CAST(invoice_number AS UNSIGNED), invoice_number;

The pattern test prevents obviously mixed identifiers from being converted. Section 8 explains REGEXP_LIKE() piece by piece.

Validate before converting

Mixed identifiers such as 'A-100' are labels, not numbers. Casting them as unsigned can produce 0 plus a warning, creating a misleading sort. Keep genuine business identifiers as strings.

4. Work with numeric data

Numeric functions are the calculator drawer. Use them to round for a business rule, find distance from a target, or organize values into useful units.

Numeric functions and what they return
Function Example Result
ROUND()ROUND(19.995, 2)Rounds to a requested number of decimal places.
TRUNCATE()TRUNCATE(19.999, 2)Cuts off extra places without rounding.
CEILING()CEILING(4.1)Returns the smallest integer not less than the input: 5.
FLOOR()FLOOR(4.9)Returns the largest integer not greater than the input: 4.
ABS()ABS(-12.5)Returns the distance from zero: 12.5.
Calculate AP balances, then format for people 
SELECT invoice_number,
       invoice_total,
       payment_total,
       credit_total,
       invoice_total - payment_total - credit_total AS balance_due,
       FORMAT(invoice_total, 2) AS total_for_display
FROM ap.invoices
ORDER BY invoice_total DESC
LIMIT 10;

FORMAT() returns a string

FORMAT(1234.5, 2) produces a display value such as '1,234.50'. Sort, filter, and calculate with the original numeric column; format only the final display value.

Floating-point values need breathing room

FLOAT and DOUBLE are approximate. Instead of testing exact equality, compare within a tolerance. For currency, prefer an appropriate DECIMAL definition.

Tolerance pattern for approximate measurements 
-- General pattern for a FLOAT or DOUBLE measurement
WHERE ABS(measured_value - 0.3) < 0.000001

5. Get, parse, and extract dates and times

Dates are not decorative labels. They are structured values that MySQL can compare, split into parts, and move forward or backward on a calendar.

Analogy: a calendar service desk

One clerk tells you the current date. Another translates a handwritten date into the database's standard form. A third extracts just the year, month, or weekday. Choose the clerk for the question you are asking.

Current date and time 
SELECT CURRENT_DATE AS today,
       CURRENT_TIME AS session_time,
       NOW() AS current_date_and_time,
       UTC_TIMESTAMP() AS utc_date_and_time;

CURRENT_DATE, CURRENT_TIME, and NOW() use the MySQL session time zone. Use UTC deliberately when systems in different time zones must agree.

Extract calendar parts from AP invoices 
SELECT invoice_number,
       invoice_date,
       YEAR(invoice_date) AS invoice_year,
       MONTH(invoice_date) AS invoice_month,
       DAYOFWEEK(invoice_date) AS weekday_number,
       EXTRACT(YEAR_MONTH FROM invoice_date) AS year_month
FROM ap.invoices
ORDER BY invoice_date, invoice_id
LIMIT 10;

Parse text only at the boundary

Convert a known text format to DATE 
SELECT STR_TO_DATE('08/25/2026', '%m/%d/%Y') AS parsed_date;
-- Result: 2026-08-25

Once a value becomes a DATE or DATETIME, keep it in that type for comparisons and calculations. Turn it into display text only at the edge of a report.

6. Format, calculate, and search date/time data

Use one tool to create a report label, another to calculate an interval, and a range predicate to search efficiently.

Overdue AP invoices 
SELECT invoice_number,
       invoice_due_date,
       DATE_FORMAT(invoice_due_date, '%b %e, %Y') AS due_date_label,
       DATEDIFF(CURRENT_DATE, invoice_due_date) AS days_past_due
FROM ap.invoices
WHERE payment_date IS NULL
  AND invoice_due_date < CURRENT_DATE
ORDER BY invoice_due_date, invoice_id;

DATE_FORMAT() returns a string for people to read. DATEDIFF() compares the date portions and returns calendar days, not business days. The original invoice_due_date remains a date.

Date arithmetic 
SELECT invoice_number,
       invoice_date,
       DATE_ADD(invoice_date, INTERVAL 30 DAY) AS date_plus_30_days,
       DATE_SUB(invoice_date, INTERVAL 1 MONTH) AS one_month_earlier
FROM ap.invoices
ORDER BY invoice_date
LIMIT 10;

Search with a half-open range

All invoices from calendar year 2022 
SELECT invoice_id, invoice_number, invoice_date, invoice_total
FROM ap.invoices
WHERE invoice_date >= '2022-01-01'
  AND invoice_date <  '2023-01-01'
ORDER BY invoice_date, invoice_id;

The inclusive start and exclusive end work for both DATE and DATETIME values. This is usually clearer and more index-friendly than wrapping the column in YEAR() inside the WHERE clause.

Search a time with the same half-open idea

The AP payment column is a DATE, so this small read-only result set demonstrates a true TIME search without changing the publisher database.

Times from 9:00 a.m. up to, but not including, 5:00 p.m. 
SELECT event_time
FROM (
    SELECT CAST('08:45:00' AS TIME) AS event_time
    UNION ALL SELECT CAST('12:30:00' AS TIME)
    UNION ALL SELECT CAST('17:15:00' AS TIME)
) AS sample_events
WHERE event_time >= '09:00:00'
  AND event_time <  '17:00:00';
-- Result: 12:30:00

Function selector lab

Choose a job to reveal the strongest beginner pattern.

Use DATE_FORMAT()

Create text such as “Aug 25, 2026” only when the final output needs a human-friendly label.

Use DATEDIFF() or TIMESTAMPDIFF()

DATEDIFF() measures days. TIMESTAMPDIFF() lets you request a unit such as hour, month, or year.

Compare the original column to a range

Use >= start and < next_period. Keep display formatting out of the filter.

7. Use CASE, IF, IFNULL, and COALESCE

Conditional expressions are the sorting desk: inspect a row, apply a rule, and return the appropriate label or fallback value.

Classify each invoice without changing it 
SELECT invoice_number,
       invoice_total,
       payment_date,
       invoice_due_date,
       CASE
           WHEN payment_date IS NOT NULL THEN 'Paid'
           WHEN invoice_due_date < CURRENT_DATE THEN 'Past due'
           ELSE 'Open'
       END AS payment_status
FROM ap.invoices
ORDER BY invoice_due_date, invoice_id;
Choosing a conditional or NULL-handling expression
Tool Best beginner use Example
CASESeveral conditions or portable, readable logicCASE WHEN ... THEN ... ELSE ... END
IF()One short MySQL-specific true/false choiceIF(payment_date IS NULL, 'Open', 'Paid')
IFNULL()One value and one fallbackIFNULL(vendor_address2, '(none)')
COALESCE()The first non-NULL value from a listCOALESCE(vendor_address2, vendor_address1, '(missing)')

NULL is “unknown,” not an empty string

Use IS NULL or IS NOT NULL to test it. Use IFNULL() or COALESCE() only when a substitute makes sense for the report.

8. Recognize patterns with regular-expression functions

A regular expression is a reusable stencil for text. It can ask whether a value follows a pattern, locate the match, extract it, or replace it in the query result.

MySQL 8 uses the Unicode-aware ICU regular-expression engine. Match behavior can also depend on character set and collation, so use the optional match type when case behavior matters.

MySQL 8 REGEXP_LIKE syntax 
REGEXP_LIKE(expression, pattern, match_type)

-- 'i' requests case-insensitive matching
SELECT vendor_name
FROM ap.vendors
WHERE REGEXP_LIKE(vendor_name, 'systems|services', 'i')
ORDER BY vendor_name;

Make matching rules explicit

Check five-digit and ZIP+4 forms 
SELECT vendor_name,
       vendor_zip_code,
       CASE
           WHEN REGEXP_LIKE(
                    vendor_zip_code,
                    '^[0-9]{5}(-[0-9]{4})?$',
                    'c'
                )
           THEN 'Expected format'
           ELSE 'Review'
       END AS zip_format_check
FROM ap.vendors
ORDER BY vendor_name;

In REGEXP_LIKE(), 'i' requests case-insensitive matching and 'c' requests case-sensitive matching. Stating the match type avoids relying on a column's collation when case matters.

REGEXP_LIKE()

Returns 1 when the pattern matches and 0 when it does not.

REGEXP_INSTR()

Returns the starting position of a match.

REGEXP_SUBSTR()

Returns the matching part of the string.

REGEXP_REPLACE()

Returns a transformed string; it does not update the table.

Read the ZIP pattern one piece at a time

^ anchors the start; [0-9]{5} requires five digits; (-[0-9]{4})? makes a hyphen plus four digits optional; and $ anchors the end. Together, the pattern checks the entire value instead of finding five digits somewhere inside it.

Pattern match is not data proof

A ZIP-shaped string can still be the wrong ZIP code. Regular expressions validate form, not real-world truth. Treat a “match” as one quality signal.

9. Rank rows and look across a window

Ranking and analytic functions keep each detail row while comparing it with related rows. The OVER clause defines which rows belong to that comparison.

Analogy: the race scoreboard

A normal row tells you one runner's time. A window function adds context: their place, the runner just ahead, or their percentile—without removing the runner from the scoreboard.

Three ranking functions 
WITH invoice_balances AS (
    SELECT invoice_id,
           vendor_id,
           invoice_number,
           invoice_total - payment_total - credit_total AS balance_due
    FROM ap.invoices
)
SELECT vendor_id,
       invoice_number,
       balance_due,
       ROW_NUMBER() OVER (
           PARTITION BY vendor_id
           ORDER BY balance_due DESC, invoice_id
       ) AS row_number,
       RANK() OVER (
           PARTITION BY vendor_id
           ORDER BY balance_due DESC
       ) AS balance_rank,
       DENSE_RANK() OVER (
           PARTITION BY vendor_id
           ORDER BY balance_due DESC
       ) AS dense_balance_rank
FROM invoice_balances
ORDER BY vendor_id, balance_rank, invoice_id;
How ties affect the three ranking functions
Balance ROW_NUMBER() RANK() DENSE_RANK()
$900111
$900211
$700332
  • ROW_NUMBER() always assigns a unique sequence; add a tie-breaker for deterministic results.
  • RANK() gives tied rows the same rank and leaves a gap afterward.
  • DENSE_RANK() gives tied rows the same rank without a gap.

Look backward and forward with LAG and LEAD

Compare each invoice with a neighboring invoice 
SELECT vendor_id,
       invoice_number,
       invoice_date,
       invoice_total,
       LAG(invoice_total) OVER (
           PARTITION BY vendor_id
           ORDER BY invoice_date, invoice_id
       ) AS prior_invoice_total,
       LEAD(invoice_date) OVER (
           PARTITION BY vendor_id
           ORDER BY invoice_date, invoice_id
       ) AS next_invoice_date
FROM ap.invoices
ORDER BY vendor_id, invoice_date, invoice_id;

The first row in a partition has no earlier row, so LAG() returns NULL there. Likewise, LEAD() returns NULL at the end unless you provide a default argument.

NTILE(4)

Places ordered rows into four numbered buckets.

PERCENT_RANK()

Returns relative rank from 0 through 1.

CUME_DIST()

Returns the rows that precede or tie the current row in the window order, divided by all rows in the partition.

FIRST_VALUE()

Returns a value from the first row of the current window frame.

Connection to Chapter 6

Chapter 6 introduced aggregate window calculations such as a running SUM(). Chapter 9 adds the nonaggregate ranking and analytic tools that answer “which place?” and “what came before or after?”

Filter a rank in an outer query

MySQL permits window functions in the SELECT list and ORDER BY, not directly in the same query level's WHERE. Put the window result in a common table expression or derived table, then filter it outside.

Top three invoices per vendor 
WITH ranked_invoices AS (
    SELECT vendor_id,
           invoice_id,
           invoice_number,
           invoice_total,
           ROW_NUMBER() OVER (
               PARTITION BY vendor_id
               ORDER BY invoice_total DESC, invoice_id
           ) AS vendor_row_number
    FROM ap.invoices
)
SELECT vendor_id, invoice_number, invoice_total
FROM ranked_invoices
WHERE vendor_row_number <= 3
ORDER BY vendor_id, vendor_row_number;

Chapter 9 takeaway

  • Choose a function for a specific job and keep ap read-only.
  • Use CHAR_LENGTH() for characters and LENGTH() for bytes.
  • Remember that CONCAT() can become NULL and FORMAT() returns text.
  • Keep date and numeric values typed until the final display step.
  • State the REGEXP_LIKE() match type when case behavior matters.
  • Use OVER to add ranking or analytic context without collapsing detail rows.
