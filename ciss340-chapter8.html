1. A data type is a column's promise

A MySQL data type tells the server what kind of value a column represents, how it can be compared, and how much precision or capacity it needs.

Analogy: choose the right container

A moving box, a filing cabinet, and a refrigerator can all hold “things,” but each protects and organizes a different kind of thing. A data type works the same way. A date belongs in a date-aware container, money belongs in an exact numeric container, and a product photo belongs in a binary container. Labeling every container “text” makes later work harder and less reliable.

Inspect before you assume

AP · read-only structure inspection 
DESCRIBE ap.invoices;

DESCRIBE reads table metadata. It lets you see each column's declared type, whether NULL is allowed, key information, and default behavior without changing the publisher database.

Meaning

What is this value?

An invoice number may contain digits but is an identifier, not a quantity used in arithmetic.

Range and precision

How large or exact?

Counts need enough integer range; currency needs a defined number of decimal places.

Behavior

How will SQL use it?

A real date can be sorted and compared as a date instead of as an arbitrary string.

Practice boundary

Use the ap schema only for read-only inspection and queries in this module. Do not alter publisher columns to “try” a new type. If a future worksheet requires a structure experiment, use only the separate sandbox named in that worksheet.

2. Character data: CHAR, VARCHAR, and TEXT

Character types store text. The important beginner decision is whether the value has a predictable short length, a variable length, or the potential to become a large body of text.

Beginner map of common character types
Type family Mental model Good fit Pause before using it when…
CHAR(n) A fixed-width slot A genuinely fixed-length code Values vary widely in length
VARCHAR(n) A flexible labeled folder Names, identifiers, email addresses, and other bounded text You cannot justify a realistic maximum
TEXT family A document drawer Long descriptions or notes The value is short, structured, or frequently indexed as a whole

An identifier is not automatically a number

Values such as invoice_number, ZIP codes, and telephone numbers may contain digits, but you do not add or average them. They may also contain punctuation or meaningful leading zeroes, so a character type is often the honest choice.

AP · observe character identifiers 
SELECT invoice_number,
       vendor_id
FROM ap.invoices
ORDER BY invoice_number
LIMIT 10;

Length is a rule, not a guess

The n in VARCHAR(n) is a maximum number of characters. Choose it from the business rule and valid data range—not simply the longest value in today's small sample.

3. Numeric data: integers, exact values, and approximations

Numeric types fall into two big groups: exact types, which preserve a defined value, and approximate types, which trade exact decimal representation for a very broad scientific range.

Whole numbers

Integer family

TINYINT, SMALLINT, MEDIUMINT, INT, and BIGINT offer increasing ranges. Pick the smallest range that safely covers the real rule, with room for growth.

Exact decimals

DECIMAL

DECIMAL(p,s) defines total precision and digits after the decimal point. It is the normal choice for currency and other values that must add exactly.

Approximate values

FLOAT and DOUBLE

These types are useful for measurements and scientific values where tiny representation differences are acceptable. Do not assume decimal equality will behave like exact money.

AP uses exact values for invoice arithmetic

AP · read-only balance calculation 
SELECT invoice_number,
       invoice_total,
       payment_total,
       credit_total,
       invoice_total - payment_total - credit_total AS balance_due
FROM ap.invoices
ORDER BY balance_due DESC
LIMIT 10;

The totals are amounts, so exact decimal arithmetic fits their meaning. The calculated alias balance_due does not change any stored value.

MySQL 8.4 numeric notes

BOOL and BOOLEAN are aliases for TINYINT(1); add an appropriate constraint when a column must accept only 0 and 1. Also avoid the deprecated FLOAT(M,D) form in new designs. Choose FLOAT/DOUBLE for approximate values or DECIMAL(p,s) for exact fixed-point values.

4. Date and time data

A date is more than text that looks like a date. A date/time type lets MySQL validate, compare, sort, and calculate with the value according to calendar and clock rules.

Roles of the main MySQL date and time types
Type Stores Beginner example
DATE A calendar date without a time of day Invoice date or due date
TIME A time value or elapsed-time range A duration or scheduled time when no date is needed
DATETIME A calendar date and clock time An appointment whose displayed wall-clock value should be preserved
TIMESTAMP A date/time value with session time-zone conversion behavior A recorded event time when that conversion behavior is intended
YEAR A year value A model year when no month or day is part of the fact

Use the AP columns as evidence

AP · find and inspect the earliest invoice date 
SELECT invoice_number,
       invoice_date,
       invoice_due_date,
       payment_date
FROM ap.invoices
WHERE invoice_date = (
    SELECT MIN(invoice_date)
    FROM ap.invoices
)
ORDER BY invoice_number;

The date columns remain dates through the comparison and sort. The nullable payment_date represents a different rule: NULL means there is no recorded payment date, not that the date type has disappeared.

MySQL 8.4 temporal note

TIMESTAMP converts between the session time zone and UTC and has a UTC range from 1970 into January 2038. DATETIME has a wider calendar range and does not perform that session-time-zone conversion. Choose the behavior your fact actually needs.

Analogy: calendar entry versus timestamped receipt

“Dentist appointment: September 4 at 2:00 p.m.” is a wall-clock appointment. “The server received this request at this instant” is an event timestamp. Both include a date and time, but their time-zone expectations differ. Choose from the business meaning, not from whichever type name sounds newer.

5. Specialized, binary, and large-object types

MySQL also provides types for restricted choices, raw bytes, and large values. These tools are useful when the domain truly calls for them; they are not automatic upgrades over ordinary relational design.

Specialized type families and their tradeoffs
Family What it represents Design question to ask first
ENUM One value from a declared set Is the set small and stable enough to place in the table definition?
SET Zero or more values from a declared set Would a related child or junction table model changing choices more clearly?
BINARY / VARBINARY Short fixed- or variable-length byte strings Are these truly bytes rather than characters in a text encoding?
BLOB family Large binary content Does storing the content in the database fit the application's size, backup, and delivery needs?
TEXT family Large character content Is this unstructured text, or should parts become searchable relational columns?
JSON Validated JSON documents with MySQL JSON operators and functions Is the structure genuinely flexible, or would ordinary related tables be clearer?
Spatial types Geometry values such as points, lines, and polygons Does the application need spatial meaning and spatial operations, not just latitude/longitude labels?

Recognition level: Murach's overview includes JSON and spatial families. This chapter identifies their purpose; detailed JSON and spatial design are beyond this beginner module.

NULL is not a data type

NULL marks an unknown or absent value. Whether it is allowed is a separate column rule. A nullable DATE is still a date column, and a nullable DECIMAL is still an exact numeric column.

6. Implicit conversion: convenient but easy to misread

MySQL sometimes converts a value automatically so two different types can participate in an expression. That is implicit conversion. It can be useful, but relying on it can hide a data or query mistake.

AP · a comparison that asks MySQL to guess 
SELECT invoice_number,
       invoice_total
FROM ap.invoices
WHERE invoice_total = '500.00';

The column is numeric while the literal is character text. MySQL can coerce the string for this comparison, but the query communicates its intent more accurately with the numeric literal 500.00.

AP · state the intended type 
SELECT invoice_number,
       invoice_total
FROM ap.invoices
WHERE invoice_total = 500.00;

Why implicit conversion deserves attention

  • Text that begins with digits can be interpreted in ways a reader did not expect.
  • Invalid conversion can produce an error, warning, or surprising value depending on the expression and SQL mode.
  • Converting a column during comparison can make an index less useful.
  • NULL usually remains NULL through a conversion; it does not become an empty string or zero automatically.

Why not store every value as VARCHAR?

Text storage would give up important rules. Text sorts lexically, so '100' can appear before '20'; invalid dates can look like ordinary strings; and arithmetic requires conversion. Accurate types let MySQL validate and operate on values according to their real meaning.

7. Explicit conversion with CAST and CONVERT

Explicit conversion tells both MySQL and the next reader exactly what representation you need. Use it deliberately at a boundary—such as parsing an input, aligning compatible expressions, or creating display text—not to cover up a poorly chosen column type.

AP · CAST values as character output 
SELECT invoice_number,
       CAST(invoice_total AS CHAR) AS invoice_total_text,
       CAST(invoice_date AS CHAR) AS invoice_date_text
FROM ap.invoices
ORDER BY invoice_date DESC
LIMIT 5;

The aliases announce that the new values are text. The original columns remain unchanged because this is a read-only result expression.

AP · equivalent CONVERT form 
SELECT invoice_number,
       CONVERT(invoice_total, CHAR) AS invoice_total_text
FROM ap.invoices
ORDER BY invoice_total DESC
LIMIT 5;
Two explicit conversion forms in MySQL
Form Reading Reminder
CAST(expression AS type) Cast this expression as the named type Clear, widely recognized conversion syntax
CONVERT(expression, type) Convert this expression to the named type MySQL also has a separate CONVERT(... USING ...) form for character sets

Conversion cannot invent valid data

Before converting imported text, inspect the source format and test edge cases. A conversion expression is not proof that every source value is valid. Check warnings and validate the result rather than assuming success.

8. Display conversion with FORMAT and CHAR

Some conversions are meant for presentation. Remember that a value formatted for people may no longer be suitable for numeric sorting or arithmetic.

FORMAT returns display text

AP · format an amount for display 
SELECT invoice_number,
       invoice_total,
       FORMAT(invoice_total, 2) AS display_total
FROM ap.invoices
ORDER BY invoice_total DESC
LIMIT 5;

FORMAT(invoice_total, 2) produces character text with two decimal places and grouping punctuation. Sort and calculate with the original invoice_total, then format near the presentation edge.

CHAR builds characters from code values

Read-only expression · character codes 
SELECT CHAR(65, 80) AS letters;

With a compatible character set, the integer codes 65 and 80 form AP. This is a specialized conversion tool, not the normal way to turn an invoice amount into readable text.

Choice lab: give the value an honest type

Choose an AP field to see the reasoning behind its type family.

Invoice number → character type

It identifies a document. It may include punctuation or leading zeroes, and arithmetic on it has no business meaning.

Invoice total → exact decimal type

It is a quantity used in arithmetic and must retain a defined scale for reliable financial totals.

Invoice date → DATE

It is a calendar fact with no time of day in this model, so a date-aware type expresses the rule directly.

9. Wrap-up and practice

Choose a type from meaning, not appearance

A value made of digits is not automatically numeric, and a date-shaped string is not automatically a date. Ask what the value means, what operations belong to it, and what range or precision the business rule requires.

Chapter 8 checklist

  • I can distinguish fixed, variable, and large character data.
  • I know when to choose an integer, exact DECIMAL, or approximate numeric type.
  • I can explain the different jobs of DATE, DATETIME, and TIMESTAMP.
  • I recognize the purposes and tradeoffs of ENUM, SET, binary, BLOB, and TEXT types.
  • I can identify an implicit conversion and replace guesswork with a clear literal or explicit conversion.
  • I remember that FORMAT creates display text, not a better numeric value.
